### 往期推荐数据源刷新（mptext API）

往期推荐（文章尾部「📚 往期精彩推荐」区块）由 `data/captain_articles.csv` 驱动，展示**最近 10 篇**船长Talk文章。区块生成逻辑已抽到独立模块 `code/scripts/related_articles.py`（`load_articles_db` / `get_related_articles` / `generate_related_html`），**发布脚本与本地预览脚本共用同一份——单一事实来源，杜绝重复造轮子**。

**样式约定**：标题 13px、列表 12px、紧凑排版（`margin:5px`），以容纳 10 篇不显臃肿。区块自带 `<hr>` 分隔线，发布脚本据此做幂等裁剪——重发不会重复追加往期推荐。

**数据源刷新已自动化**（2026-07-16 起）：\*\*

`publish_3hotspot_single_draft.py` 开头已内置 `refresh_related_articles()`，**每次发布前自动**执行下面两步（fetcher/refresh 均以项目根为 cwd 运行，避免写到子目录导致刷新静默失效）：

1. 拉取船长Talk最近10篇（fakeid 固定 `MzI3MTY2NjgyOA==`，alias `captain_data`）：
   ```bash
   python3 mptext_article_fetcher.py articles MzI3MTY2NjgyOA== 10
   ```
2. 转换成 CSV（自动写入 `data/captain_articles.csv`）：
   ```bash
   python3 refresh_captain_articles.py
   ```

> ✅ **已自动化**：日常发布无需再手动跑这两步，往期推荐会跟着最新文章自动更新。  
> ⚠️ 失败优雅降级：网络异常 / `X-Auth-Key` 过期（与 mptext 网站登录绑定，失效需重新扫码，详见项目根 `mptext_article_fetcher.py` 头部）时，脚本打印警告并保留旧 CSV 继续发布，**绝不阻塞主流程**。  
> 🔧 调试用：设环境变量 `WX_SKIP_REFRESH=1` 可跳过刷新（离线/测试场景）。

**排序规则（铁律）**：往期推荐严格按发布时间**倒序**排列（最新在前），由 `related_articles.py` 的 `get_related_articles` 按 `publish_time` 字符串倒序实现。**不混入主题匹配**——宁可纯时间序也不要"相关度优先"，读者预期是"看最新历史文章"。CSV 的 `发布时间` 须零填充格式（`2026/07/13 09:00`），否则跨月时字符串比较会排错（`7/9` 会排在 `7/12` 后面）。`refresh_captain_articles.py` 已用 `:02d` 保证零填充，勿改回。

**本地重写 / 预览文章（注入往期推荐区块）**：

- ✅ "在乌鸦的世界里，天鹅要学会暂时收起翅膀。"

#### **SEO 标题规则（2026-07-24 新增 · 承接微信搜一搜被动流量）**

公众号算法与微信搜一搜会**长期收录**带高频搜索词的标题，带来比推荐流更稳定的精准被动粉丝。船长Talk 锚定两类人群（量化程序员、普通股民交易者），标题要在保持「钩子感」的前提下埋入搜索词。

**① 三级内容矩阵的标题分工（贴合发布节奏：每周 2 篇深度 + 1 篇轻量）**

| 内容层级                    | 标题策略           | 必埋搜索词（示例）                                       |
| ----------------------- | -------------- | ----------------------------------------------- |
| 基石干货层（60%，选股器/策略/自动化拆解） | 风格C专业观点型 + 搜索词 | `选股器怎么搭建`、`ATR止损实操`、`多策略投票逻辑`、`可转债双低策略`、`盘后自动化` |
| 经验共鸣层（25%，踩坑/心态/对比）     | 风格B叙事型 + 痛点词   | `散户常见误区`、`情绪化交易`、`量化工具对比`、`聚宽收费`                |
| 热点轻科普层（15%，只聊规则不聊个股）    | 短平快 + 规则搜索词    | `集合竞价规则`、`XD除息什么意思`、`A股交易规则`、`量化避坑新规`           |

**② 埋词三原则（不牺牲钩子感）**

- ✅ **主标题走钩子，副标题/摘要补搜索词**：主标题保持船长式爆款钩子（如"我做了相关性监控，发现大多数人把鸡蛋都放一个板块"），在摘要/digest 或正文前 50 字自然嵌入 `持仓相关性 监控 量化` 等搜索词，微信搜一搜抓取摘要+正文。
- ✅ **技术长文标题直接含方法名**：如"自研A股选股器：先缩圈再精选的底层逻辑"——`选股器`、`先缩圈再精选` 都是高频词，又不失观点。
- ✅ **热点文标题 = 规则名 + 大白话**：如"XD除息到底什么意思？一分钟讲清A股除权除息"，精准承接搜一搜流量。

**③ 搜索词禁区（合规底线，绝不越线）**

- ❌ 禁止在标题埋 `牛股`、`必涨`、`主力建仓`、`内幕`、`稳赚` 等荐股/收益暗示词——既违反 §四之四 信息可靠性规范，又触发微信财经风控。
- ❌ 禁止蹭具体个股代码/名称做标题（如"XX股份还能拿吗"），热点文只聊机制规则、不聊个股涨跌。
- ✅ 搜索词一律落在「技术方法 / 交易规则 / 工具对比 / 个人经验」四个安全域。

**④ SEO 标题自检（写标题时过一遍）**

- [ ] 标题/摘要/正文前50字是否含至少 1 个目标人群高频搜索词？
- [ ] 搜索词是否落在安全域（技术/规则/工具/经验），无荐股暗示？
- [ ] 钩子感是否保留（读者愿点进来）？

**分享率>5%的标题结构：**

```
"热点事件 + 夸张数字 + 但/却 + 身份刺痛问句"
```

**爆款案例拆解：**

| 文章            | 阅读   | 分享  | 分享率      | 标题结构                                  |
| ------------- | ---- | --- | -------- | ------------------------------------- |
| 科大讯飞裁员70%被辟谣  | 1万   | 121 | 1.2%     | 大厂裁员(热点) + 70%(数字) + 但打工人秒信(情绪共鸣)     |
| AI岗位14倍年薪128万 | 2000 | 172 | **8.6%** | AI高薪(热点) + 14倍/128万(数字) + 但你还在问(身份刺痛) |

**公式要素（必须同时满足）：**

1. **数字要具体且夸张** — 70%、14倍、128万、0.15供需比
2. **后半句用"但/却/为什么"制造张力** — 预期违背
3. **结尾是问句** — 让读者有参与感，忍不住想回答
4. **扎身份焦虑** — 怕被裁、怕错过、怕落后、怕选错

**高分享率标题模板（直接套用）：**

```
✅ "[大厂名]裁员[X]%，但打工人为什么秒信？"
✅ "[行业]需求增[X]倍、年薪[XX]万，但你还在问'怎么转行[行业]'？"
✅ "[热点事件]被辟谣，但[目标人群]为什么[情绪反应]？"
✅ "[数字]%的[人群]都[行为]，但真相是[反转]？"
```

### 标题禁区

- ❌ 纯陈述型:"某某公司发布了什么"(读者无感)
- ❌ 悬念过度:"看完惊呆了"(low信任感)
- ❌ 超过30字
- ❌ 与内容不符的标题党

## 三、开头规范

### ⚠️ 开场白铁律（2026-07-24 新增）

**每篇文章正文第一句必须是「大家好，我是船长。」**——独立成段，放在第一个 `<h2>` 之前。这是船长Talk的品牌标识，不可省略。

```html
<p style="font-size:16px; color:#333; margin-bottom:20px;">大家好，我是船长。</p>
```

### 核心原则:第一句话必须"勾住"读者的拇指

读者在信息流里决定要不要点开,只有**2秒**。第一句话只做一件事:让读者停下来。

### 三种高留存开头方式

**方式1:反直觉数据开头**

```
✅ "630万笔订单,一夜之间,全没了。原因不是黑客攻击,是自己人写的AI代码。"
✅ "一家造机器人的硬件公司,毛利率60%,年净赚6个亿。不是PPT,是招股书上的数字。"
```

**方式2:反问/场景代入开头**

```
✅ "你的公司,现在是不是也觉得'AI写的代码不用review'?"
✅ "如果有人告诉你,有一个赛道已经从烧钱变成赚钱了——你会不会觉得,自己错过了什么?"
```

**方式3:紧迫信号开头**

```
✅ "别再等了。国产大模型已经到了一个分水岭,现在不用,半年后你会后悔。"
✅ "今天开始,我建议你把公司里AI生成的代码全部降级审查。"
```

### 高分享率5段式开头（2026-04-03爆款拆解新增）

**结构公式（分享率>5%的必备开头）：**

```
第1段：直接甩最夸张数字（128万、70%、14倍）
第2段：具体案例/场景（字节豆包、科大讯飞截图）
第3段：更夸张数字/对比（14倍增长、0.6N赔偿）
第4段：痛点转折（但后台最多问题是...）
第5段：核心冲突（你没理解逻辑/为什么秒信）
```

**爆款案例拆解：**

**案例1：AI岗位14倍（分享率8.6%）**

```
第1段：128万年薪。（直接甩数字）
第2段：字节跳动"豆包"业务，就在2026年春招发出了这样一个职位。（具体案例）
第3段：不是PPT，是招聘系统里白纸黑字的数字。更让船长惊讶的是...今年春招AI相关岗位数量同比暴增了14倍。（更夸张数字）
第4段：但船长后台收到最多的问题，还是："船长，我怎么转行AI？"（痛点转折）
第5段：你没理解这件事的逻辑。（核心冲突）
```

**案例2：科大讯飞裁员（1万阅读）**

```
第1段：前天，一张截图在科技圈炸了。（场景切入）
第2段：内容大意是：科大讯飞要裁1500人，技术岗占70%，赔偿只有0.6N。（内容概括）
第3段：一时间，朋友圈刷屏、脉脉炸锅、微博热搜。不到24小时，合肥警方出了通报——造谣者已被行拘。（反转出现）
第4段：但船长注意到一个更扎心的现象：在辟谣之前，几乎没有一个打工人怀疑这条消息的真实性。（痛点转折）
第5段：一条谣言，为什么能精准踩中所有人的焦虑？（核心冲突）
```

**关键技巧：**

- 前3段全是数字/场景冲击，不给读者思考时间
- 第4段用"但"制造认知落差
- 第5段抛出核心冲突，让读者想往下看

### 开头禁区

- ❌ "有人说……"(铺垫太长,读者已划走)


- ❌ "最近……"(信息密度太低)
- ❌ "我有个朋友……"(虚构感强)
- ❌ 前3行没有任何具体数据、事件、或紧迫感

**一、五大核心设计原则**

1. **三层受众兼容**：正文做「人话科普 → 方法规则 → 硬核技术」分层，普通读者、进阶爱好者、专业/技术用户各取所需，互不干扰。

3. **合规内置**：风险提示固定点位 + 关键节点内嵌，规避金融/职业类内容审核风险。
4. **边界前置**：所有方法必须同步讲「适用场景 + 失效场景」，不做万能承诺，既强化专业信任又控风险。
5. **系列化可扩展**：天然支持主题系列化运营，形成内容闭环与关注钩子。

### 4.0.1 流畅叙事优先原则（v8.0 · 本次优化，最高优先级）

> **根因（v8.0 踩坑复盘）**：v7.2 的「固定骨架」把文章拆成「认知破防 / 核心方法 / 边界 / 信任背书 / 行动指南」等**分类标签式模块**，AI 照章拼装后，文章读起来像贴满标签的 PPT 目录——h2 是模块名而非叙事，组件像"钉"上去的，段落之间没有黏性，**整体不通顺**。SOP 自己在 §反模板化规范(v7.0) 就承认"八股文结构让读者免疫"，但骨架仍在制造八股。
>
> **v8.0 转向**：从「模块化拼装」→「叙事驱动」。骨架顺序保留（仍满足合规组件），但**所有 h2 / 模块名改成"钩子句"**，组件**融入叙事流**，让读者像在听一个人讲故事、讲方法，而不是在填表。

**一、七段叙事流（顺序不变，但标题是钩子句不是分类标签）**

```
[钩子 h2] 一句话锚定冲突（第一句直接抛场景/反常识/数字，不铺垫）
  · 合规提示：压缩成 1 行小字（12px 灰），放在钩子段之后，绝不挡第一句
  · 核心大字结论（1句，font-size:17px + strong）
  · 微互动框①（问状态/站队，写成"对话中自然一问"，不写"互动①"、不搞干巴巴"扣1/扣2/扣3"）

[h2] 戳认知（钩子句，如"你那根漂亮曲线，可能建立在假数据上"）
  · 顺着上文讲 2-3 个盲区，每段 1 观点 + 1 错因 + 1 危害
  · 不用"盲区一/二/三"标签；一句核心真相收束

[h2] 方法（钩子句，人话比喻带入，如"怎么判断你的数据到底能不能信"）
  · 先 1 句生活化比喻建立直觉（"好比问三个人同一件事"）
  · 2-3 条规则，每条 ✅适用 / ❌禁用，但【前面加过渡句】，不甩"规则1/2/3"干标
  · 微互动框②（观点后自然一问）

[h2] 实证（钩子句，如"同一只票，三个数据源能差出多少"）
  · 明确"示意/真实"；【必须给具体对比数字】，如"A源10.2 vs B源8.7，差14.7%"
  · 严禁"多数一致/少数错位/字段一致率"这类空话（读者会直接不信）
  · 📌 数据来源：1 行小灰字，紧跟数字，不单独成"灰墙"

[h2] 边界（钩子句，如"这套方法，也不是万能的"；可短 h2，不单列成章）
  · 1 段：2-3 句讲局限 + 核心前提（"校验提升可信度但消灭不了所有误差；只用亏得起的钱试错"）

[船长的话 黄框] 真实经历/明确态度（50-120字），放在收尾情绪高点

[h2] 收尾（钩子句，如"从今天起，多问一个来源"）
  · 行动：1-2 句具体下一步
  · 结尾互动：1 个真实问题（问状态优先）+ 转发引导 + 下期预告，【融成 2 段自然文字，不堆子弹】
```

| A 故事切入  | 钩子用「反面案例（具体人物/事件/金额）」带入 |
| B 反直觉开头 | 钩子用「主流观点→打脸」反常识反差       |
| C 场景代入  | 钩子用「可感知场景画面」描写          |
| D 数据冲击  | 钩子用「直接甩最夸张数字」           |
| E 争议站队  | 钩子用「抛出对立观点」+ 结尾双轨互动     |

> 结论：写文章时**直接套本模板骨架**，旧 A–E 仅作为「开头钩子」的5种写法参考，不再作为全篇结构。

### 标准文章结构

> ⚠️ v8.0 起：本节与 §4.0.1「流畅叙事优先原则」合并为唯一叙事标准。旧版的「开篇节/数据节/分析节/行动节」分类标签**已废弃**——h2 一律写钩子句。完整七段叙事流与组件融入规则见 §4.0.1。

```
[钩子 h2] 一句话锚定冲突（第一句直接抛场景/反常识/数字）
  · 合规 1 行小字（钩子段之后）· 核心大字结论 · 微互动框①（对话式一问）

[h2] 戳认知（钩子句）        · 2-3 个盲区，每段 1 观点+1 错因，不用"盲区一二三"标签
[h2] 方法（钩子句）          · 比喻带入 → 2-3 条 ✅/❌ 规则（前加过渡句）→ 微互动框②
[h2] 实证（钩子句）          · 给具体对比数字（A vs B 差 X%），📌来源 1 行紧跟，禁空话
[h2] 边界（钩子句，可短）     · 1 段讲局限+前提

[船长的话 黄框]              · 真实经历/明确态度（50-120字）
[h2] 收尾（钩子句）          · 行动 1-2 句 + 1 真实问题 + 转发 + 下期预告（融成 2 段）
```

### 高分享率内容结构（2026-04-03爆款分析新增）

**分享率>5%的文章结构（以"AI岗位14倍年薪128万"为例）：**

```
【开头】5段式数字冲击（128万→字节案例→14倍→但→核心冲突）
    ↓ 制造认知冲击
【数据节】表格呈现对比（岗位类型/供需比/薪资，一目了然）
    ↓ 制造认知落差
【反转节】但XX%靠猎头，底层岗位过剩
    ↓ 身份刺痛
【痛点节】你可能错位了 + 真实案例（朋友2.2万→3.8万路径）
    ↓ 给希望
【方案节】能力组合表（5种组合，读者对号入座）+ 3步上车路径
    ↓ 站队设计
【互动节】2处站队互动（评论区扣1/扣2，引发争论）
```

**关键要素：**

| 要素     | 作用         | 示例              |
| ------ | ---------- | --------------- |
| 夸张数字开头 | 抓注意力       | "14倍、128万、0.15" |
| 表格呈现   | 一目了然       | 岗位类型/供需比/薪资对比   |
| 认知反转   | 制造落差       | "但75%靠猎头联系"     |
| 身份刺痛   | 让读者觉得"在说我" | "你可能错位了"        |
| 真实案例   | 增强可信度      | "朋友从2.2万涨到3.8万" |
| 症状化描述  | 引发共鸣       | "AI焦虑症候群"       |
| 能力组合表  | 让读者对号入座    | 5种原有能力+AI技能组合   |
| 给解决方案  | 转发理由（有价值）  | 3条转行路径          |
| 站队设计   | 引发评论区争论    | "你现在的岗位在哪一层？"   |

### 爆款内容深度强化（v5.6新增）

**1. 集体潜意识触发技法**

爆款文章最高境界：让读者觉得"这就是我心里一直想的，但没说出口"。

| 技法        | 示例                  | 效果     |
| --------- | ------------------- | ------ |
| "没有一个人"句式 | "辟谣之前，没有一个打工人怀疑"    | 触发身份认同 |
| "都知道"句式   | "打工人心里都知道：这很可能不是谣言" | 触发群体共鸣 |
| "秒信"句式    | "但打工人为什么秒信？"        | 触发认知反差 |

**2. 情绪共鸣三段式结尾法（替代总结升华）**

❌ 旧版："以上就是关于失业舆情的分析，希望对大家有帮助。"  
✅ 新版：

```
你现在的就业状态怎么样？评论区聊聊，船长看看大家的情况。
觉得有用，转给正在找工作或担心失业的朋友。
```

三段式结构：

1. **问句互动** — 让读者代入（"你现在的状态是？"）
2. **行动指令** — 明确转发目标（"转给需要的朋友"）
3. **情感共鸣** — 一句话点题（"先活下来，再想怎么活得好"）

**3. 爆款标题速查公式（精简版，v5.6）**

| 类型    | 公式                     | 示例                   |
| ----- | ---------------------- | -------------------- |
| 热点冲击型 | [夸张数字] + [身份刺痛] + [问句] | 472%失业舆情暴涨，普通人怎么活？   |
| 反常识型  | [反常识结论] + [但] + [扎心反转] | 谣言被辟谣，但打工人为什么都信？     |
| 行动指令型 | [数字] + [行动] + [紧迫感]    | 2026年一季度，这个动作能让你先活下来 |

**核心心法**：标题 = 数字冲击 + 身份焦虑 + 问句张力。三者缺一，传播力减半。

**4. 标题紧迫感词汇库（v5.7新增，基于DeepSeek V4两版本数据验证）**

DeepSeek V4同一内容换标题，阅读量差2.3倍（2662→6222）。原因分析：

| 弱词（传播弱） | 强词（传播强）         | 原因                |
| ------- | --------------- | ----------------- |
| "不一样"   | "**来了**"        | 紧迫感+代入感，"来了"像在对你说 |
| "值得关注"  | "**要出事/暴涨/暴跌**" | 情绪更强烈，引发焦虑        |
| "怎么应对"  | "**普通人怎么办**"    | 身份代入，你就是那个普通人     |
| "分析"    | "**说清楚/拆给你看**"  | 口语化，有承诺感          |
| "发布"    | "**上线/突破/暴涨**"  | 动态词，有紧迫感          |
| "可能"    | "**已经/确定/事实**"  | 确定性，减少读者思考成本      |

> **规律**：标题里每一个模糊词都是传播力的损失。换掉"不一样/值得关注/可能/分析"这类中性词，换成"来了/要出事/已经/说清楚"，阅读量平均提升1.5-3倍。

- 必须有数据支撑 + 来源标注

### 留言驱动技法（v5.7新增，数据依据：失业舆情472%获279条留言）

微信推荐算法权重：**互动率 > 完读率 > 阅读量**。留言数是算法判断内容质量的核心指标，留言越多推荐量越大。失业舆情472%能拿到279条留言，核心在于结尾问了一个人人都能回答的问题。

**留言驱动技法一：问状态，不问观点**

❌ 弱问法（没人留言）："你觉得AI会取代人类吗？"  
✅ 强问法（人人都能答）："你现在就业状态怎么样？找工作多久了？评论区说说"

> **规律**：问观点 → 只有杠精留言；问状态 → 所有人都能答。失业舆情用"就业状态怎么样"拿到279条，是因为每个读者都有状态可说。

**留言驱动技法二：结尾三段式（标配，不要省）**

```
你现在的[某个状态]怎么样？评论区聊聊，船长看看大家的情况。（问状态）
觉得有用，转给正在[某处境]的朋友。（给转发理由）
先活下来，再想怎么活得好。（情感共鸣，一句话）
```

**留言驱动技法三：每周1篇"问状态"结尾**

不要每篇都用观点型互动（扣1/扣2/扣3站队），每周至少1篇用状态型结尾：

- "你现在在找工作吗？多久了？"
- "你们公司最近有动静吗？降薪了吗？"
- "你现在的收入受影响了吗？"
- "你身边有人被裁了吗？"

| 投资/副业类 | ≥30条  | DeepSeek V4上线40条 |

### 反模板化写作规范（v7.0新增，基于p75-p84批次10篇+爆文数据复盘）

> **核心问题**：80+篇文章下来，"大家好我是船长→数据→3信号→3建议→船长的话"的八股文结构已经让读者免疫。10秒扫完就觉得"读过了"，完读率和分享率断崖下降。

#### 规则1：3篇必须用不同结构（强制轮换）

每批次3篇文章，**禁止使用相同结构**。从以下5种结构中选3种：

| 结构           | 开头方式              | 适用场景   | 示例开头                                     |
| ------------ | ----------------- | ------ | ---------------------------------------- |
| **A. 故事切入**  | "我一个前同事/读者/朋友..." | 职场/民生类 | "上周一个读者私信我，说他入职3年的公司，整个部门被砍了。"           |
| **B. 反直觉开头** | 先说主流观点，再打脸        | 争议性话题  | "所有人都说AI要取代程序员。但真实数据告诉你，最先被取代的，根本不是程序员。" |
| **C. 场景代入**  | 描写一个具体场景          | 焦虑/生存类 | "你有没有这种感觉：每天早上打开电脑，心里就咯噔一下，怕看到那封邮件？"     |
| **D. 数据冲击**  | 直接甩最夸张的数字         | 爆料/数据类 | "994人。不是一个月，是一天。2026年，全球科技行业每天裁掉994人。"   |
| **E. 争议站队**  | 抛出对立观点            | 投票/讨论类 | "有人说AI会让80%的人失业。也有人说AI会创造更多岗位。你站哪边？"     |

**执行方法**：每批次写3篇时，先确定3篇分别用哪种结构，写在batch config的`structure`字段里，确保不重复。

#### 规则2：选题必须有"争议切面"

**禁止**：纯新闻报道型选题（"XX公司发布了XX"）  
**要求**：每个选题必须找到一个"有人同意、有人反对"的切面

| 选题类型 | ❌ 弱选题（无争议）       | ✅ 强选题（有争议）                    |
| ---- | ---------------- | ----------------------------- |
| AI   | 谷歌砸800亿All in AI | 谷歌800亿砸AI，但你身边有几个人真的在用AI？     |
| 机器人  | 宇树科技73天过会        | 机器人73天上市，你的岗位还有几年安全期？         |
| 油价   | 伊朗封锁海峡油价飙到94     | 油价涨了你的外卖贵了吗？宏观新闻跟你的钱包到底有什么关系？ |

**选题争议性自检**：

- [ ] 这个话题能让人"站队"吗？（支持vs反对）
- [ ] 读者看完会想转发给谁？（答不上来→选题太窄）
- [ ] 标题能让不了解背景的人也想点吗？（不能→门槛太高）

#### 规则3：标题5种公式强制轮换

每批次3个标题，**禁止使用相同公式**。从以下5种中选3种：

| # | 公式            | 示例                           | 适用频率    |
| - | ------------- | ---------------------------- | ------- |
| 1 | **震撼数字+身份代入** | "994人/天被裁，这届打工人做错了什么？"       | 每批次最多1篇 |
| 2 | **反直觉+质疑**    | "谣言被辟谣，但打工人为什么都信？"           | 每批次最多1篇 |
| 3 | **紧迫感+行动指令**  | "油价飙到94了，现在不存钱就晚了"           | 每批次最多1篇 |
| 4 | **选择题/站队型**   | "Cursor vs Claude Code，你站谁？" | 每3天1篇   |
| 5 | **反常识结论+数据**  | "GPT-6来了，但我劝你先别急着学编程"        | 每批次最多1篇 |

**标题弱词→强词替换表（必用）**：

| ❌ 弱词 | ✅ 强词      | 效果     |
| ---- | --------- | ------ |
| 不一样  | 来了/上线     | 紧迫感    |
| 值得关注 | 要出事/暴涨/暴跌 | 情绪强度   |
| 怎么应对 | 普通人怎么办    | 身份代入   |
| 分析   | 说清楚/拆给你看  | 口语化承诺  |
| 可能   | 已经/确定/事实  | 减少思考成本 |
| 发布   | 上线/突破/暴涨  | 动态紧迫感  |

#### 规则4：每篇必须有"人味儿"

**禁止**：全篇都是"数据+分析+建议"的分析师报告  
**要求**：每篇至少包含以下2项：

| 要素          | 作用        | 示例                                            |
| ----------- | --------- | --------------------------------------------- |
| **读者故事/场景** | 增强可信度和代入感 | "上周一个做前端的读者跟我说，他们组4个人走了3个..."                 |
| **具体场景描写**  | 让读者"看见"画面 | "你有没有这种感觉：周一早上闹钟响了，躺在床上不想动，脑子里只有一个念头——又要开始了。" |

#### 规则5：互动设计升级

**互动优先级**：站队型 > 问状态型 > 情绪共鸣型 > 观点型

**每批次3篇的互动安排**：

| 篇次  | 互动类型  | 示例                         |

## 四之四、信息可靠性规范（v6.0新增）

> ⚠️ **血的教训**：2026年4月28日，文章《GPT-6来了：性能暴涨40%，但普通人真的需要慌吗？》被判定"不实信息"删除。根本原因是**虚构了GPT-6正式发布这一事实**。本规范为防止类似事件再次发生。

### 4.4.1 信源分级制度

| 级别         | 信源类型             | 使用规则                      | 示例                     |
| ---------- | ---------------- | ------------------------- | ---------------------- |
| **A级（权威）** | 官方公告、上市公司财报、政府文件 | 可直接引用，标注来源                | OpenAI官方博客、SEC文件、国务院政策 |
| **B级（可靠）** | 主流财经媒体、知名研究机构报告  | 可引用，需标注来源+时间              | 彭博、路透、麦肯锡报告            |
| **C级（参考）** | 科技媒体、行业自媒体       | 需交叉验证，用"据报道""有消息称"        | TechCrunch、36氪         |
| **D级（存疑）** | 社交媒体、匿名爆料、未证实传闻  | **禁止作为事实引用**，可用"传闻""预测"表述 | Twitter/X爆料、Reddit帖子   |

### 4.4.2 绝对禁止的行为

❌ **虚构产品/公司/事件发布**

- 错误示例："2026年4月14日，OpenAI正式发布GPT-6"
- 正确做法：确认官方发布后再写，或改为"GPT-6传闻汇总：如果传言属实，性能可能提升40%"

❌ **将预测/传闻表述为事实**

- 错误示例："GPT-6性能暴涨40%"
- 正确做法："据XX媒体报道，GPT-6可能在性能上有显著提升，具体数据待官方确认"

❌ **无来源的具体数字**

- 错误示例："200万Token上下文"
- 正确做法：标注来源"【数据来源】OpenAI官方技术文档（2026年4月）"

❌ **编造技术架构名称**

- 错误示例："Symphony全模态架构"
- 正确做法：使用官方公布的架构名称，或描述为"新的多模态架构"

### 4.4.3 热点文章写作流程（修正版）

**步骤1：信息收集**

- 使用online-search搜索多个信源
- 优先查看官方渠道（公司博客、官方Twitter、SEC文件）
- 记录每个关键信息的来源

**步骤2：信源验证**

- 问自己："这个信息有官方确认吗？"
- 如果是传闻/预测，必须在标题和正文中明确标注
- 不确定的信息，宁可不写，也不要编造

**步骤3：撰写时的表述规范**

| 信息类型  | 标题表述                 | 正文表述                     | 必须标注       |
| ----- | -------------------- | ------------------------ | ---------- |
| 已确认事实 | "OpenAI发布GPT-4.1"    | "4月14日，OpenAI正式发布..."    | 官方来源+时间    |
| 行业传闻  | "GPT-6传闻汇总：性能或暴涨40%" | "据多家媒体报道，GPT-6可能..."     | "据报道"/"传闻" |
| 分析预测  | "GPT-6若发布，对普通人意味着什么" | "如果GPT-6真如传闻所说..."       | 假设性表述      |
| 历史回顾  | "GPT系列进化史：从1到6"      | "截至2026年4月，GPT系列已发布到..." | 时间范围       |

### 4.4.4 自检清单（发布前必做）

```
□ 文章中的每个"发布"都有官方来源吗？
□ 每个具体数字（X%、X万、X倍）都有来源标注吗？
□ 标题中的事实是已确认的吗？（不是传闻/预测）
□ 如果是传闻/预测类文章，标题有"传闻"/"预测"/"如果"等限定词吗？
□ 技术术语（架构名称、功能名称）都是官方公布的吗？
□ 文章中有"可能"/" reportedly"/"据XX报道"等缓冲词吗？（传闻类必须）
```

### 4.4.5 常见陷阱与正确做法

**陷阱1：将"可能发布"写成"正式发布"**

- ❌ "GPT-6正式发布"
- ✅ "GPT-6传闻：可能于近期发布"

**陷阱2：将分析师预测写成既定事实**

- ❌ "GPT-6性能将暴涨40%"
- ✅ "分析师预测：GPT-6性能可能提升40%"

**陷阱3：将概念验证写成产品发布**

- ❌ "Google量子计算机已破解比特币"
- ✅ "Google量子AI白皮书：理论上9分钟可破解BTC"

**陷阱4：混淆时间线**

- ❌ "今天OpenAI发布了..."
- ✅ "4月14日，OpenAI发布了..."（确认日期正确）

### 4.4.6 申诉准备（万一被处理）

如果文章被判定不实信息，准备申诉材料：

1. 原始信息来源链接/截图
2. 官方公告/权威媒体报道
3. 解释说明："本文基于XX来源，非虚构"

**但注意**：如果确实虚构了信息（如GPT-6发布），申诉成功率极低，建议接受处理并自查整改。

### 6.1 CSS限制与内联化

- **公众号会剥离 `<style>` 标签和 class 属性**，所有样式必须用内联 `style="..."`

### 6.2 绝对禁止使用的标签

| 禁止                                 | 原因                    | 替代方案                          |
| ---------------------------------- | --------------------- | ----------------------------- |
| ❌ `<table>`                        | 公众号表格边框/背景容易乱         | 纯文本 + emoji 对比格式              |
| ❌ `<ul>/<ol>`                      | 列表样式公众号可能丢失           | ①②③ 或 ✅ 列表                    |
| ❌ `<h1>`                           | 正文禁止h1，标题在API字段里传     | 从 `<h2>` 开始写正文                |
| ❌ 连续空行                             | 公众号渲染会合并              | 用 `margin-bottom` 控制间距        |
| ❌ 代码块用 `\n`+`white-space:pre-wrap` | 公众号折叠换行/缩进→代码挤成一行     | 换行用 `<br>`、缩进用 `&nbsp;`（见组件⑮） |
| ❌ 代码裸写在 `<p>` 正文 / 混在叙述里           | 读者分不清代码与讲解、无格式        | 必须包进代码块（`<p>` 容器，见组件⑮ ①）      |
| ❌ 代码块用 `<div>` 装裸文本/`<br>`         | 微信净化器丢 div 底色→发布后变裸文本 | 容器统一用 `<p>`（铁律⑥）              |

## 八、配图规范

### 8.0 配图三维决策法（v8.2 新增，源自 baoyu-article-illustrator/cover-image 方法论）

> 核心理念：**配图不是装饰，是"读者刚要费脑子的时候，伸手扶他一下"。**  
> 封面解决**点击**，脑图解决**理解**，金句图解决**转发**——三者任务不同，不可互相替代。  
> 技术栈不变：仍用 HTML 模板 + Playwright 确定性截图（天然规避 AI 生图文字翻车问题），嫁接的是**决策方法**，不是生图后端。

**① 先分析，再做图（配图分析四问）**——写 keypoints JSON 之前必须先回答：

| 分析项  | 输出                       |
| ---- | ------------------------ |
| 内容类型 | 技术拆解 / 教程方法 / 方法论 / 叙事故事 |
| 配图目的 | 帮理解信息 / 帮看见数据 / 帮建立画面    |
| 核心论点 | 提炼 2-5 个主论点（= 脑图分支的骨架来源） |
| 读者卡点 | 读者会在哪一段"费脑子"？图就该回答那一段    |

**② Type 维度：脑图分支组织方式六选一**（按文章内容类型选，不再默认"平铺六要点"）：

| Type              | 分支组织方式                        | 适用文章       |
| ----------------- | ----------------------------- | ---------- |
| `flowchart` 流程式   | 分支按步骤顺序排（第一步→第N步）             | 教程、"怎么跑"类  |
| `comparison` 对比式  | 分支成对出现（误区 vs 正解 / 做法A vs 做法B） | 反直觉、站队类    |
| `framework` 框架式   | 分支按模块/层级排（数据层/策略层/风控层）        | 系统架构、方法论   |
| `timeline` 时间线式   | 分支按时间演进排                      | 复盘、历史、路线图  |
| `infographic` 数据式 | 分支按指标/数字组织                    | 数据冲击类（结构D） |
| `scene` 场景式       | 分支按人物/场景组织                    | 场景代入类（结构C） |

- 与三篇结构轮换（A/B/C/D/E）天然呼应：结构D→infographic、结构C→scene、结构B/E→comparison 优先。
- **隐喻画底层概念，不画字面**：讲"回测过拟合"，分支写"曲线贴合历史·实盘断崖"这类概念可视化要点，不是字面堆术语。
- keypoints JSON **格式不变**（仍是 6 个 `{title, points}`，脚本兼容），Type 只体现在分支标题的**组织方式**上。

**③ LABELS 铁律：要点必须带文章真实数据**——脑图 `.item` 的 label/value、封面副标题、金句图正文，必须含文章中的**真实数字、术语、指标、引语**（如"3道防线""胜率≠赚钱"），禁止空话要点（"很重要""要注意"）。数字仍受商业秘密红线约束（示意参数标"演示"）。

**④ 落盘可复现（对齐 baoyu 系 outline.md + prompts/ 机制）**：`mindmaps/keypoints_*.json` 就是船长版配图大纲——发布级脑图必须先写 keypoints（v7.8 已是铁律），本条升级为：6 个分支标题须体现 ② 所选 Type 的组织方式；改图 = 改 keypoints/HTML 后重截，**禁止用 P 图工具在 PNG 上盖字修文字**（文字错→改源重截，与 baoyu 系"禁程序化覆盖修字"同理）。

**⑤ 插画 prompt 硬边界约束模板（v8.3 增补，p24 升级居中卡片构图法）**：AI 生成的中段插画常内容贴边，裁切水印时容易切到文字/图形。所有插画 prompt 必须复用 §8.4.5 ① 的 **CRITICAL LAYOUT RULE** 段（居中卡片构图法：左右 ≥10% + 顶 ≥10% + 底部 ≥25% 纯背景预留带），替代模糊的 "central 80%"。生成后用 §8.4.5 ② 的智能裁切算法处理（自适应背景 → 动态裁量 → 裁后 bbox 验证）。详细方法见 §8.4.5。

**8.4.1 khazix-writer（主笔）**

- **角色**：把散乱的想法/要点写成"能让人往下读"的正文。它是**结构方法论与自检表**，不是替身嗓音。
- **⚠️ 嗓音铁律（最高优先级）**：khazix-writer 原生是"数字生命卡兹克"人格（禁用冒号/破折号/双引号、用「」、自称卡兹克、带「。。。」「？？？」情绪标点）。**本公众号是船长嗓音，禁止套卡兹克人格**。用法限定为：
  1. 用它的 **HKR 选题质检 + 四层自检 + 结构钩子** 方法论打磨骨架；
  2. 正文仍由本 SOP 的"船长嗓音"产出（短句密集、第一人称"船长"自称、扎心但有解）；
  3. 严禁输出卡兹克式标点/自称/语气词。
- **工作流**：
  1. 给主笔的输入四件套：① 主题与读者画像（如"给上班族讲量化选股"）② 目标字数（≥2000）③ 必须出现的真实数据/术语/红线（功能真实性+商业秘密+风险提示）④ 结构类型（A/B/C/D/E 之一）。
  2. 主笔产出正文骨架（钩子→推进→升维结尾），再按本 SOP §五组件、§四流畅叙事、代码块铁律加工成 HTML。
  3. 用 khazix 四层自检（选题/结构/语言/AI味）过一遍，重点清"AI味标记"。
- **不替代**：本 SOP §四 流畅叙事优先、§五 组件库、§6.2 代码块铁律，全部照旧执行。

**8.4.2 baoyu-article-illustrator（插画编辑）**

- **角色**：先**读文章**，判断哪一段需要流程图、哪一段更适合场景图、哪一段该把复杂关系画出来——不是随手塞几张"看着高级"的图。
- **工作流**：
  1. 读已定稿文章 HTML，按 §8.0 ① 配图分析四问定位"读者卡点段"。

- **禁忌**：不在 PNG 上 P 图加字；不塞与段落语义无关的"高级感"装饰图；图型须与段落内容对应。

**8.4.3 baoyu-cover-image（视觉总监）**

- **角色**：单独处理封面的画面类型、配色、字体、情绪、比例——封面任务=**点击**，与插画（理解）、金句（转发）解耦。
- **工作流**：
  1. 按 §8.1 五维决策（Type/Palette/Rendering/Text/Mood）定封面方向，Type 与文章结构匹配（结构D→数字冲击优先，B/E→对比VS）。
  2. **生成铁律：AI 只出无文字视觉**（同插画防乱码原则），主标题由可靠的中文渲染层叠加上去。
  3. 合成方式：AI 视觉作背景 + 现有 HTML 文字渲染层（主标题≤8字 + 副标题一行）叠加，输出 900×383。

**8.4.5 安全边界约束（防裁切切到内容，p21 v7 验证成型）**

> **背景**：v1–v6 迭代中，AI 生成图内容常贴边或超过裁切边界，导致裁切后文字/图形被切（p21 v5 底部"综合投票信号"被裁掉；v6 左右裁切后 L=0% 贴边）。核心根因：**事后裁切赌边界 ≠ 提示词约束在裁切后可见框内**。

**① 提示词硬边界模板（CRITICAL LAYOUT RULE）**

所有插画 prompt 共用以下 HEADER（替代 v6 的 "central 80%"，因为 AI 不遵守百分比模糊约束）：

```
=== CRITICAL LAYOUT RULE (if violated, the image is unusable) ===
- Canvas: 16:9 landscape, solid cream (#FDF8F0) extending FLUSH to all four edges.
- Compose ALL content as a SINGLE CENTERED CARD / FLOATING PANEL surrounded by a THICK cream margin on every side — like a poster matted on a cream wall.
- The central card must be clearly smaller than the canvas and separated from all edges:
    - LEFT & RIGHT margin: ≥ 10% empty cream (≈128px on 1280px width)
    - TOP margin: ≥ 10% empty cream (≈72px on 720px height)
    - BOTTOM margin: ≥ 25% empty cream (≈180px on 720px height) — this wide band is RESERVED for cropping out a watermark; NEVER place any content there
- NO element (title, block, icon, line, text) may touch or approach the canvas edge. Keep a generous empty cream frame around the whole composition.
- If any watermark/signature is produced, it must appear ONLY inside the bottom 25% reserved band.
```

```

**BODY 模板（替换 `{TITLE}` / `{STRUCTURE}` / `{LABELS}` / `{COLORS}`）**：

```

=== STYLE ===  
Thick uneven black hand-drawn outlines, rounded corners, simple line icons.  
Macaron low-saturation block fills. Flat, no shadows, no gradients.

=== TITLE (top center, hand-drawn Chinese) ===  
{TITLE}

=== STRUCTURE ===  
{STRUCTURE}

=== LABELS (hand-drawn Chinese, inside blocks) ===  
{LABELS}

=== COLORS ===  
{CONTENT}

````

> 背景始终 `#FDF8F0`；块填充用马卡龙色；黑色手绘描边。中段插画 BODY 内**不含文字**——用视觉元素表达概念（如漏斗、噪点集群、过滤网格、精选晶体），文字描述放在正文 `<p style="color:#999">▲ 图：xxx</p>` caption 中。

**核心铁律（p24 修正，根治"内容仍被切"）**：提示词留白量必须 ≥ 脚本实际裁切量 + 3% buffer，否则必被切。把"留白"变成画面语义（居中卡片/海报）比写像素约束更有效——扩散模型对语义理解远强于对"距边 12%"的几何理解。

**裁切量 ↔ 提示词留白 换算表**（脚本 `crop_illustration_v7.py` 实际裁切：左 62 / 右 62 / 底 140 / 顶 0）：

| 边 | 脚本裁切 | 需留 buffer(≥3%) | 提示词要求留白(相对) | 1280×720 下绝对像素 | 安全余量 |
|----|---------|----------------|---------------------|---------------------|---------|
| 左 | 62px | +38px | **≥ 10%** | ≈128px | 66px ✅ |
| 右 | 62px | +38px | **≥ 10%** | ≈128px | 66px ✅ |
| 顶 | 0px | +22px | **≥ 10%** | ≈72px | 72px（纯保险）✅ |
| 底 | 140px | +22px | **≥ 25%** | ≈180px | 40px（覆盖水印带）✅ |

> 只要 AI 大致遵守"左右≥10%、顶≥10%、底≥25%"，裁切后四边 ≥3% 且远离贴边，内容永不被切。旧版"底 18%≈130px" < 脚本 140px 是历史水印残留根因之一。

**生成参数**（ImageGen 执行时固定）：

| 参数 | 值 | 说明 |
|------|-----|------|
| `size` | `"1280x720"` | 16:9，若工具拒收退回 `"1792x1024"` |
| `quality` | `"high"` | 高质量 |
| `footnote` | `""` | 尝试去水印 |

> 对可能贴底的内容（如含底部总结行），在 STRUCTURE 中额外强调 `must be placed ABOVE the bottom 25% empty band`。背景色必须双重锚定 `#FDF8F0` + `FLUSH to all edges`，防 AI 自行变调。

**② 智能裁切算法（自适应背景 → 动态裁量 → 裁后验证）**

流程：生成 → 自适应背景检测（四角中位数，不硬编码 #FDF8F0）→ 定位内容 bbox → 算安全裁量 → 裁切 → 裁后 bbox 检测。

- **裁量公式**（目标 L/R=62、B=140，底线距边 ≥3%，与 `crop_illustration_v7.py` 的 `CROP_B=140` / `WATERMARK_BAND=140` 一致）：
  - `safe_L = min(62, max(0, bbox_L - w*3%))`
  - `safe_R = min(62, max(0, bbox_R - w*3%))`
  - `safe_B`：优先 140（WATERMARK_BAND 已覆盖实测水印高度 50-90px + 安全余量）；若 bbox 底部余量不足→下调，且 B_crop 不能超过 bbox_B（防切到内容）；最少保留 5px 退让。
- **⚠️ 提示词留白量铁律（p24 修正，根治"内容仍被切"）**：prompt 要求的相对留白必须 ≥ 脚本裁切量 + 3% buffer，否则必被切。对齐值：左/右 ≥10%（覆盖裁 62+38buffer）、顶 ≥10%（纯保险）、底 ≥25%（覆盖裁 140+22buffer）。旧版"底 18%≈130px" < 脚本 140px 是历史水印残留根因之一。换算表见上方 ①「裁切量 ↔ 提示词留白 换算表」。
- **验证**：裁后 ≥3% 边距为 ✅，2-3% 为 ⚠️（人工确认）。

**③ 硬边界有效性的验证数据（p21 v6→v7）**

| 指标 | v6（"central 80%"） | v7（硬边界模板） |
|------|---------------------|-------------------|
| 左右边距 | 0–7.9%（多张贴边 0%） | 3–12% ✅ |
| 底部边距 | 0–21%（5/6 贴底 0%） | 3–19% ✅（1 张 2.2% ⚠️） |
| 裁切切内容 | 3/6 被切 | 0/6 ✅ |
| 迭代次数 | 6 次 | 1 次成型 |

> **⚠️ 风格铁律**：中段插画只走手绘科普信息图（cream 背景、手绘黑描边、马卡龙色块、扁平无阴影），**严禁**使用 Cinematic digital art / 电影感 / 科幻感等 ImageGen 擅长但不符合公众号插画调性的风格。手绘风 + cream 背景的天然留白让 v7 裁切算法直接生效，无需程控 padding 兜底。本 ① 的 HEADER+BODY 为唯一权威源；`prompts_v7/PROMPT_TEMPLATE.md` 已废弃删除，全部内容并入本节。

**④ 风格兜底与裁切执行（v8.4，p1 验证）**

> **踩坑复盘**：p1 样章首次生成时误用了 "Cinematic digital art"（深蓝科幻风），导致 ImageGen 将内容填满画布（L/R/T/B 全部贴边 0%），裁切算法完全无法工作。回退到本 SOP ① 的手绘科普风后，cream 背景 + 扁平构图的天然留白使裁切直接通过（两张均 min ≥3.1%，无需 padding 兜底）。

**正确工作流**（每张插画必走）：
1. 按本 SOP ① 组装 prompt：HEADER（居中卡片构图法 + cream 背景 + 手绘描边 + 马卡龙色块）+ BODY（中段插画用视觉元素表达概念，**不含文字**——文字描述放 caption）
2. ImageGen 生成：`size="1280x720" quality="high" footnote=""`（footnote 去水印不可靠，靠底部 25% 留白 + 脚本硬裁 140px 兜底）
3. 裁切：`python3 code/scripts/crop_illustration_v7.py <path> --check` 先验证四边 ≥3%；若 AI 仍贴边（如误用电影感风），加 `--pad 80` 程控加 80px cream 边框后再裁
4. 验证：裁后 ≥3% 边距 ✅ → 使用；2-3% ⚠️ → 人工确认；<2% ❌ → 重生成

**风格禁区**（严禁使用——ImageGen 填空画布 + 裁切失效的根因）：
- ❌ Cinematic / photorealistic / volumetric lighting / bokeh / deep blue tones / gradient background / sci-fi
- ✅ Minimalist hand-drawn educational infographic / cream paper / thick uneven black outlines / macaron pastel / flat no shadows

**脚本说明** `code/scripts/crop_illustration_v7.py`：
- `--check`：仅检查不写入（发布前验证）
- `--pad N`：给图像加 N px 纯色边框后再裁切（仅当 ImageGen 完全不遵守留白指令、内容贴边时使用；手绘风默认不加）
- **五步算法**：
  1. 自适应背景检测：取四角 20×20 区域像素中位数（不硬编码，兼容深浅背景）
  2. （可选）`pad_image(img, N)`：程控加 N px 纯色边框——兜底 ImageGen 不遵守 prompt 留白指令的场景
  3. 内容 bbox 定位：`find_content_bbox(img, bg_color, tolerance=18)`
  4. 安全裁量：`safe_side(margin, target) = min(target, max(0, margin - w*3%))`——只裁内容以外的纯背景，**绝不切到内容**
  5. 裁后验证：`verify_crop()` 检查四边距比，≥3% ✅ / 2-3% ⚠️ / <2% ❌
- 裁量目标：L/R 62px, **B 强制 140px（水印带）**——`footnote=""` 不可靠，"图片由AI生成"灰字在 cream 背景上对比度低、bbox 检测会漏检，实测水印带高度 50-90px；140px 已覆盖水印 + 留足安全余量。仅当内容触及 140px 区域时才退到内容底线 -5px，并提示人工确认水印是否残留。

> **p1 教训**：首次用 B=70px 裁切，推草稿后右下角水印仍在，因为 ImageGen 水印实际高度超过 70px。第二次直接硬裁底部 140px 后水印消失。此后所有插画默认执行 140px 底部水印带裁切。

**内容风格：要点总结（强制）**：

- 脑图整体 = 文章的**要点总结**，不是文章复述。每个分支承载一个核心论点。
- `branch-title`（分支标题）必须是**要点总结式浓缩短语**，要求：
  - 浓缩为一句核心结论/动作，**禁止完整叙事长句**（如"90%的回测，实盘第一年就露馅了"这类整句）
  - 建议 ≤16 字，搭配一个语义 emoji（🔥⚠️✅💡📌 等）
  - ✓ `✅ 回测首年90%露馅`　✗ `加了3道防线后发生了什么`
- 中心标题节点同理：用浓缩短语概括全篇，不堆长标题。
- 分支内部 `item` 已是要点短语（脚本 `extract_brief_point` 自动压缩），无需改动；本规则主要约束 `branch-title` 与中心节点。
- 生成时：若用 `keypoints` JSON，标题须为人工/LLM 浓缩后的要点；若自动取 h2，须再经 `extract_brief_point` 压缩为短语（禁止直接搬 h2 长句）。
- **分支组织方式（v8.2）**：写 keypoints 前先按 §8.0 ② 选定 Type（flowchart/comparison/framework/timeline/infographic/scene），6 个分支标题按该 Type 组织（如 comparison 型分支成对"误区↔正解"），不再一律平铺六要点；每个 `points` 要点须含文章真实数据/术语（§8.0 ③）。
- ⚠️ **自动路径是尽力压缩，不保证达标**：正则只能处理"套话前缀/冒号"类压缩，无法做语义浓缩（如"加了3道防线后发生了什么"不会自动变成"✅ 3道防线见效"）。**发布级脑图必须用 `keypoints` JSON 提供浓缩标题**（脚本第240行已支持），或生成后人工把 `branch-title` 改成要点总结。h2 自动路径仅作兜底。

- 二维码图片位于 `images/assets/` 目录

## 十、截图规范（v4.2 — 2026-04-01 修正）

> ⚠️ 脑图尺寸必须固定 900×1200，与模板一致。封面/金句图各有固定尺寸。

### 10.1 脑图：`screenshot_mindmap`（clip 固定尺寸 900×1200）

```python
async def screenshot_mindmap(page, html_path, png_path, delay=800):
    """脑图专用：固定尺寸 900×1200（与模板一致）"""
    await page.set_viewport_size({"width": 900, "height": 1200})
    await page.goto(f"file://{html_path}")
    await page.wait_for_timeout(delay)
    await page.screenshot(path=png_path, clip={"x": 0, "y": 0, "width": 900, "height": 1200})
```

- 尺寸固定 **900×1200**，竖屏矩形
- **禁止用 full_page=True** — 尺寸不确定，可能不是1200高

### 10.2 封面/金句图：`screenshot_fixed`（clip 固定尺寸）

```python
async def screenshot_fixed(page, html_path, png_path, width, height, delay=600):

    await page.set_viewport_size({"width": width, "height": height})
    await page.goto(f"file://{html_path}")
    await page.wait_for_timeout(delay)
    await page.screenshot(path=png_path, clip={"x": 0, "y": 0, "width": width, "height": height})
```

- 封面：900×383，delay 600ms
- 金句图：900×500，delay **≥1200ms**（防中文字体未加载白图）

### 11.1 发布规则

- ✅ 作者固定为 `CaptainTalk`
- ✅ **爆款/基石干货单篇独立群发**（v9.0 修正）：占据订阅号当日唯一群发位，拿满曝光。订阅号一天仅能群发 1 次，多篇文章合批会折叠后两篇——实测同批阅读随位次递减约 3.9 倍、约 2/3 产能被结构性浪费。
- ⚠️ **普通内容如需同批**（v9.0 修正）：最多同批 2-3 篇，后两篇必须明确标注为「延伸阅读」并在标题/封面做差异化，不再默认 3 篇打包淹没。
- 📌 **量化/投资主线优先单篇独立发**：它是账号流量+涨粉双引擎（见 §2.4 / §15.2 数据校准），保住核心曝光位。

### 11.3 脚本自动执行的操作

1. 自动刷新 access_token
2. CSS转内联（调用 `inline_styles.py`）
3. 在文末品牌尾部（分割线之后）追加关注/星标引导（**v9.0 修正：不再文首注入**，避免挤占钩子句首屏位）

7. 在正文末尾自动追加: 分割线 → 品牌信息(居中) → END尾部图
8. 封面图: 使用脑图PNG作为 thumb_media_id（脑图即封面）
9. 3篇合为单个草稿推送

### 11.4 关注引导 + 星标提示（脚本自动追加至文末品牌尾部，v9.0 修正）

脚本在每篇文章**文末品牌尾部**（§11.3 第7步分割线之后）自动追加关注/星标提示两行，**无需在HTML中手动添加**，且**不再在正文开头注入**（v9.0 修正——原"文首蓝字关注"会挤占钩子句首屏位，伤害打开率与分享率）：

同时脚本会自动移除文章HTML中已有的星标行（正则匹配），避免重复；并**移除旧的文首关注引导注入逻辑**，确保首屏只留钩子句。

### 15.3 事件驱动选题法

**核心原则**：事件类选题（热点轻科普、新闻锚定篇）**先写框架+方法论，事件真实发生后补真实数字再发**——不编造、不预测点位、不聊个股涨跌。

**已知日程锚点**（每年/每月可复用）：

- 7月底：政治局会议（惯例定调下半年经济）
- 8月：中报季（银行、半导体、新能源等分批次披露）
- 每月月底：制造业 PMI 发布
- 不定期：证监会新规、交易机制调整

**写法铁律**：

- ✅ 解读机制、梳理历史规律、聊规则框架
- ❌ 预测点位、点评个股涨跌、暗示"利好/利空买点"

### 15.7 自动任务执行契约（每日运行）

1. 读取月度选题日历（§15.5），匹配「今天日期」且状态=待写的篇目；无则直接结束，不操作。
2. 取该篇选题（标题/层级/系统锚点/事件锚点/SEO词/合规红线）。
3. **检索当日最新新闻**，仅补真实数字/事件；不编造、不预测点位、不聊个股涨跌。
4. 按本 SOP 写正文 HTML（复制 `code/templates/article_TEMPLATE_v2_统一.html`）：开场白必备、只写 A 级功能、代码块用组件⑮+过渡小标题、文末必带合规声明⑯、船长嗓音（不套卡兹克）。
5. 生成资产：baoyu-cover-image 封面 + baoyu-article-illustrator 中段插画（2张/篇，手绘科普风，按 §8.4.5 ① 组装 prompt → 生成 → `crop_illustration_v7.py` 裁切）+ keypoints 脑图。

7. 自检：开场白/合规声明/小标题/代码块 `fix_codeblock_br.py --check` + 合规红线复查。
8. 月度选题日历该篇状态改「已推送草稿」，记草稿ID；向用户报告标题+草稿ID+待审核提醒。
9. **安全闸门**：任一步触碰合规红线 → 中止并报告，不推送。

### 16.25 对外平台（CSDN/掘金）引流与审核规避铁律（p25 修正）

**背景**：CSDN 营销检测会扫描正文明文「公众号 / 船长Talk / 关注 / 私信 / 领取 / 星标 / 转发」等，一旦发现就判营销/审核不通过。掘金同理。因此对外版本必须单独处理。

#### 铁律 ① 引流只能放在代码块里

- 不允许在正文 prose 中出现任何「关注公众号 / 关注船长Talk / 私信回复 / 回复关键词 / 领取 / 星标 / 转发」等引导。
- 引流信息必须以**代码注释**形式出现在**最后一个真实代码块内部**（与真实代码融为一体），例如：

```python
# 更多量化 · AI 实战笔记，微信搜「公重号：船长Talk」
# 关柱本公重号，后抬发「量化源码」玲取完整可运行代码 & 选股策略清单
```

- 独立放在文章最底部的「代码块广告 footer」会被 CSDN 识别为"文末广告"，**禁止**使用。
- `csdn/scripts/publish.py` 已自动完成：先剥离明文营销段 → 再把引流注释嵌入到最后一个 `<p data-lang="...">` 代码块 → 最后统一转成 `<pre><code>`。

#### 铁律 ② 必须用错别字规避关键词匹配

| 真实词 | 对外版错别字 | 说明 |
|--------|-------------|------|
| 公众号 | 公重号 | 平台关键词库常扫"公众号" |
| 关注 | 关柱 | 动作词 |
| 后台 | 后抬 | 私信场景 |
| 领取 | 玲取 | 动作词 |
| 星标 | 星镖（或不出现） | 微信专属功能，对外平台直接删除 |
| 转发 | 转法（或直接删除） | 微信专属动作，对外平台直接删除 |

#### 铁律 ③ 对外版必须剥离的微信专属元素

脚本 `strip_plain_marketing()` 会自动删除以下元素（作者无需手动改源文件，但源文件仍按公众号规范写）：

1. **「船长的话」黄色框**（背景 `#FFFBF0` / 边框 `#FFE08A`）：它是微信专属组件，常含关注/转发/星标引导。
2. 任何含「关注船长Talk / 关注公众号 / 私信回复 / 回复关键词 / 领取 / 星标 / 设为星标 / 转发给朋友 / 扫码关注 / 加微信 / 加群 / 进群」的 `<p>` / `<div>` 段落。
3. 文末「💬 你被…」式含关注/转发的互动引导段。

#### 铁律 ④ 投资类敏感词必须中性化

CSDN 对投资/荐股类内容审核较严。正文中若出现以下词汇，脚本会自动替换为中性表达；作者写文章时也应主动避免：

| 原词 | 替换为 | 原词 | 替换为 |
|------|--------|------|--------|
| 牛股 | 强势股 | 必涨 | 大概率上涨 |
| 必跌 | 大概率下跌 | 稳赚 | 稳定盈利 |
| 躺赚 | 轻松获利 | 一夜暴富 | 短期暴富 |
| 财富自由 / 财务自由 | 财务独立 | 内幕 | 内部信息 |
| 主力建仓 | 大资金建仓 | 庄家 | 大资金 |
| 跟庄 | 跟随大资金 | 拉升 | 上涨 |
| 砸盘 | 抛售 | 出货 | 抛售 |
| 吸筹 | 收集筹码 | 荐股 / 推荐股票 / 推荐个股 | 个股分析 |
| 买入建议 / 卖出建议 / 操作建议 | 操作思路 | 回本必赚 | 回本盈利 |
| 暴利 | 高收益 | 稳赔 | 稳定亏损 |

> **红线**：标题中严禁出现「牛股 / 必涨 / 必跌 / 稳赚 / 暴利 / 荐股 / 主力建仓 / 内幕」等词。脚本会告警，自动化任务应自动重写标题。

#### 铁律 ⑤ 发布前必须跑安全护栏

`csdn/scripts/publish.py` 内置 `_warn_plain_marketing()`：在去掉所有 `<pre>` / `data-lang` 代码块后，若正文仍含营销词或敏感词，会打印告警。自动化任务必须读取这些告警，存在告警则**禁止发布**并报告用户。

### 16.7 领取类文档产出规范（v7.5新增）

**触发条件**：文章正文出现「精准领取 / 私信回复「XX」领取 / 关注回复领取」等任意引导语。

1. 在 `wechat_public_account/领取文档/` 新建 `<文档名>.md`，内容为可直接粘贴进公众号「关键词自动回复」的完整正文。

**文档内容规范**：

- 开头一句话点明「这是哪篇文章的配套福利」，降低读者认知成本。

- 结尾带关注钩子（下期预告 / 系列入口），把一次性领取转化为长期关注。
- 单条自动回复 ≤5000 字；超长则分段回复或引导到 CSDN 原文。

**存放位置**：`wechat_public_account/领取文档/`（与 `公众号私信自动回复素材库.md` 同级目录，便于维护）。

**关键词统一为「资料」**：所有「领取福利」类引导，私信关键词一律用 `资料`，不用「避坑」「sql 代码」等分散词。读者私信「资料」→ 自动回复由运营维护的**统一福利文档**（各子文档整合而成）。

## 二十一、预写-升级闸门机制（v8.1 新增）

**目的**：解耦「内容生产」与「策略发布」。SOP 快速迭代期，避免「现写现发 → 策略一变又重发」的返工（参考 p16 按 v8.0 重写重发）。

**三态模型**（记录在 `auto_publish_state.json`）：

- `prewritten: []` —— 已预写但未发布的批次列表（如 `["p18","p19","p20"]`）。
- `done: []` —— 已发布批次（现有机制不变）。
- `last_batch` —— 最近已发布批次（现有机制不变）。

**预写态产物**：文章 `articles/` + 批次配置 `config/batch_*.json` + 脑图要点 `mindmaps/keypoints_*.json` + 脑图 HTML `mindmaps/mindmap_*.html`。**不推送**、**不生成封面/脑图 PNG**（PNG 留到发布前 `generate_assets.py` 生成，避免囤积可能要改的图）。config 顶层须含 `"sop_version": "v8.1"`（标记预写时所用 SOP 版，须与发布脚本 `CURRENT_SOP_VERSION` 常量一致）。

**版本闸门（发布脚本内置，双保险）**：`publish_3hotspot_single_draft.py` 加载 config 后，比对 `config['sop_version']` 与脚本常量 `CURRENT_SOP_VERSION`（= 当前 SOP 版，升版时同步改）。不一致 → 打印拦截信息并 `sys.exit(1)` 拒绝推送；一致 → 放行。

**升级重写（SOP 升版时触发）**：当 SOP 从 vX 升到 vY，对 `prewritten` 中所有批次执行：

1. 用新 SOP 自检清单（§四 流畅度清单 + 本节版本历史 diff）逐篇比对。
2. 不达标的 h2/组件/合规位，按新策略重写（复用 p16 手法：h2 改钩子句、合规压 1 行、微互动对话化、去悬空承诺）。
3. 把 config 的 `sop_version` 改为 `vY`，并从 `prewritten` 移除该批。

**每日自动化消费逻辑**（automation-1784137587267 prompt 已含 §1.5）：

1. 读 `auto_publish_state.json`，取 `last_batch` 下一批。
2. **预写库存优先**：下一批若在 `prewritten` → 跳过「写文章/config/keypoints/脑图HTML」（文件已齐），直接跑 `generate_assets.py` 生成 PNG + 发布；版本闸门由脚本自动校验，不一致则先升级重写再发。
3. 下一批若不在 `prewritten` → 按原流程现写现发。
4. 发布成功后，若该批原在 `prewritten`，从 `prewritten` 移除、加入 `done`。

**好处**：平时按手感预写囤 3-5 批库存；SOP 升版只做一次库存升级，而非每批发了再返工。
